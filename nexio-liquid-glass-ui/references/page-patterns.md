# 页面范式 Page Patterns

不是"每个 App 都长这样"，而是**这套语言的语法**：层怎么叠、留白怎么算、平板怎么分栏、外观页怎么开洞。先选范式，再填内容。

## 0 通用层叠骨架（所有页面）

```
┌ 背景（壁纸 / surface）
├ 内容层（可滚动）  ←—— 录制进 LayerBackdrop（采样源）
├ 顶栏层（渐进模糊带 + 折叠标题 + 玻璃按钮）   ←—— 不参与采样，避免采到自己
├ 浮层（下拉菜单 / 开洞预览 / 弹层）          ←—— 采样"壁纸层 + 内容层"的合成
└ 底部导航（独立两块玻璃：胶囊 + 圆钮）
```

四条铁律：
1. **采样层只包内容**。顶栏与浮层在采样层之外，否则玻璃会折射到自己。
2. **顶栏单独成层**，页面级模糊糊不到标题；整页共用一个模糊层会把页内浮层一起糊掉。
3. **overScroll 作用域每页一个**，内容与顶栏必须读同一个实例，否则越界回弹驱动不了顶栏材质。
4. **`recordKey` 覆盖一切会改变被采样像素的因素**（数据版本、当前页、主题）。给 `null` = 每帧重录，滚动时会很贵；给错 = 玻璃停在旧帧。

## 1 首页（课表 / 今日，tab 页）

| 项 | 口径 |
|---|---|
| 顶栏 | 折叠 52dp，标题居中（手机）/ 左对齐（平板），左侧天气/日期徽标，右侧两颗 42dp 玻璃按钮 |
| 星期行 | 40dp，位于折叠标题之下；今日：星期名 + 日期用主色，其余 `onSurface` / `actions` |
| 内容顶 | `星期行底 + 2dp`；模糊带只是装饰，不参与内容定位 |
| 模糊带高 | 有状态栏 `120 + sb`；无状态栏 `160`；竖排 tab 折叠态 `112` |
| 底栏 | 胶囊 + 圆钮，见 components §6 |
| 翻周 | 星期行文字带按动画列数摊开，网格瞬时重排 |
| 空单元格 | 不画边框，靠留白；"午休/晚休"用一条 8–12dp 高的浅色胶囊分隔 |

内容顶精确式（与原实现同源）：

```
top = max( weekRowBottom + 2, appBar + topBarHeight - 78 )
```

其中 `weekRowBottom = sb + 52 + (有 sb ? 0 : 40) + 40`。新项目不必抄这个减 78 的魔法数，但**内容顶必须只由"标题底 + 星期行"决定**。

## 2 文档页（设置子页 / 详情页）DocumentPageScaffold

```
ProgressiveBlurTopBar(72dp + 头部组件 72dp = 144dp 糊带)
  └ CollapsibleTopAppBar(大标题 + 折叠标题, showLargeTitle = true)
       ├ startAction = 42dp 玻璃返回按钮（图标 25dp，光学偏移 x -2dp）
       └ endAction = 42dp 玻璃按钮（可 1–2 颗，间距 8dp）
  └ PageHeaderContent（分段胶囊 / 搜索框，钉在标题下，跟标题一起让出高度）
content(...) → LazyColumn，contentPadding = 16dp / 平板 20dp，底部 60dp
```

| 参数 | 值 |
|---|---|
| 糊带基高 | 72dp（+ 状态栏）；`statusBar == 0` 且非折叠态时取 120dp；折叠屏无顶部状态栏时 72 − 8 = 64dp |
| 有头部组件时 | +72dp（合计 144dp） |
| 大标题 | 32sp，折叠后变 52dp 标题栏 |
| 返回按钮 | 42dp，图标 25dp，`performHapticFeedback = false`（返回不震） |
| 页面级模糊 | `pageBlurDp` 可选；内容层/顶栏层/浮层各自持缓存，半径不变复用实例 |
| 采集重录 | 折叠动画期间按 `heightOffset` 帧差判断，**只在绘制期求值**，不触发重组 |
| 浮层接管顶栏 | `chromeBlocked = true` 时拦下返回/更多点击，转给 `onChromeBlockedTap` |

## 3 设置页（列表型首页）

| 项 | 值 |
|---|---|
| 左右内边距 | 16dp（平板 20dp） |
| 分组之间 | 12dp |
| 组内 | `Card(insideMargin = 0)` + 多行，不画分隔线 |
| 小标题 | `SmallTitle` 14sp Bold `#8F9CAE`，12/8dp 内边距，组前 8dp |
| 图标块 | 28dp / 圆角 8dp / 图标 17–22dp |
| 行 | 标题 17sp Medium + 摘要 14sp 60%，末端箭头 40% |
| 底部 | `60dp` 或 `原生导航栏 inset + 24dp` |
| 搜索 | 有搜索时头部组件 50dp 高，糊带 +72dp |
| 滚动 | 与文档页共用 `SharedScrollBehavior`；切换子页时**不要**重建，否则标题位置跳 |

平板右栏里同一套页面要 `forceCollapsedTitle = true`（不显示大标题），且宿主已处理横向安全区时页内**不要**再套一层 `safeDrawing`（否则左边多出状态栏高度）。

## 4 平板：侧栏 + 双栏

断点 **600dp** 宽。

| 形态 | 规则 |
|---|---|
| 折叠轨 | 玻璃遮罩宽 **84dp** + 距屏幕左缘 **12dp**（合计 96dp 避让） |
| 展开面板 | 宽 = `max(屏宽 × 22%, 200dp + 12dp)` |
| 项 | 高 52dp，行间 4dp，图标 26dp，标签 12dp 间距；顶部工具条 48dp |
| 竖屏 | 展开 = **纯叠层**（浮在内容上 + 压暗），内容避让恒为 84+12，展开不重排 |
| 横屏 | 展开 = 内容**让位**，避让宽度 84+12 → 展开宽 |
| 顶栏 tabs | 折叠态是一颗按钮，展开时 morph 成顶部胶囊（按钮宽 48、tab 78、内边距 4） |
| 右栏文档 | 不显示大标题，返回键可隐藏；横向 inset 由宿主处理 |

实现要点：展开/折叠只在**状态切换那一帧**重排一次，中间帧全部走 `graphicsLayer` 平移或真实 `offset`（用真实 offset，玻璃才会重新采样；纯绘制变换会让卡片玻璃停在变形前画面）。

## 5 开洞式外观页（把 App 当"可裁剪的画"）

这是整套语言里最有辨识度的一页：主界面**缩进一个连续圆角洞里**，壁纸在外，控件浮在洞外。

```
┌ 壁纸铺满
│  ┌ 洞（屏幕圆角，内容按 scale 缩进）  ← 实时预览当前外观
│  └
├ 顶部一排：取消（玻璃胶囊 42dp）  [分段胶囊：图标切换]  应用（主色胶囊 42dp）
├ 底部一排：红色圆形×（56dp） | 分隔线 | 调色盘圆钮 | 视图切换圆钮
```

| 项 | 值 |
|---|---|
| 洞的形状 | 连续圆角，半径 = 设备屏幕圆角；缩进时半径按 `radius / scale` 补偿 |
| 进出 | `CustomizePageEasing`；遮盖保持 32ms、缩放 400ms、淡出 120ms |
| 顶部按钮 | 42dp 高胶囊；`取消` 用玻璃、`应用` 用主色实底 |
| 分段胶囊 | 42dp，图标模式（不带文字） |
| 底部圆钮 | 56dp；红色 `error` 底 + 白 ×；中性玻璃；调色盘/网格图标 |
| 壁纸 | 全屏，不被模糊；洞内内容才被缩放 |
| 实时性 | 洞内就是真实页面（同一个 Composable），不是截图贴图；改参数即时生效 |

用途迁移：任何"边看边调"的场景（主题、字体、卡片密度、地图样式、剪辑滤镜）都可以套这个骨架——**把被调对象缩进洞，把调节器放到洞外**。

## 6 列表详情 ⇄ 全屏

- 点卡片进详情：用 morph（`motion.md` §5），卡片 bounds → 全屏，圆角从卡片圆角插到屏幕圆角。
- 详情页顶栏沿用文档页骨架，但**不给大标题**（进来时已经在卡片上读过标题）。
- 返回手势可预测：滑动位移直接映射进度，松手按速度吸附；中途可打断。

## 7 弹层

| 场景 | 形态 |
|---|---|
| 选中详情（课程详情） | `BlurBottomSheet`，顶部把手 22dp 命中 / 4dp 可视，滚动到底有 `TextHandleMove` 触感 |
| 确认 / 导入 | `Dialog` 贴底，底角 `屏幕圆角 − 外边距`，下限 32dp；主次按钮横排，主按钮右 |
| 更多菜单 | 从 42dp 按钮 morph 展开成 16dp 圆角面板，玻璃独立 key |
| Snackbar | 胶囊，浮在底栏上一个浮起量 |

## 8 新项目落地顺序（推荐）

1. **搭骨架**：背景层 + 内容层（先不给玻璃）+ 顶栏 + 底栏。此时应是"干净的 Miuix 页面"。
2. **接主题**：深浅两套色 + 字号 + 连续圆角，逐屏对 `design-tokens.md`。
3. **接玻璃**：先只给顶栏两颗按钮与底栏两块玻璃（最小面积），确认采样正确、滚动才出材质。
4. **扩到卡片**：只在有壁纸/有内容的页面给卡片玻璃；纯色列表页不必给。
5. **上动效**：卡片入场 → 文字换字 → morph（最后做，最容易翻车）。
6. **平板**：断点 600dp，侧栏 + 双栏；先把"竖屏叠层"跑通再做横屏让位。
7. **降级**：`NONE` 档逐屏过一遍，确认没有"只有模糊才成立"的布局。

## 9 跨平台差异（同一套语言，不同宿主）

| 平台 | 处理 |
|---|---|
| Android | edge-to-edge；状态栏/导航栏 inset 进顶栏糊带与底栏浮起；API 31/33 决定玻璃档 |
| iOS | 右上角那排（"更多" UIMenu + 切换）由**原生 chrome 接管**，Compose 侧整排不渲染；页内返回仍可自绘；底部 home indicator 用 `safe-area` 换算浮起量 |
| HarmonyOS | 顶栏仍由 Compose 画，右上角两颗交给 ArkUI；底部导航宿主接管时 Compose 侧**只留同高空位**（`56 + 浮起量`） |
| 桌面 | 标题栏与窗口控制交给系统；鼠标 hover 需要额外状态（触屏没有）；`RenderEffect` 可能不可用 → 走 `FROSTED` |
| 折叠屏折叠态 | 竖排 tab bar，屏顶无状态栏：糊带 `120 - 8dp`，内容顶不补那 40dp 星期行，标题右侧额外内边距避开竖排栏 |
| 平板 | 侧栏（§4）；右栏文档页 `forceCollapsedTitle`、隐藏返回键、横向 inset 由宿主处理 |

判断"宿主是否接管"用一个 Local（如 `LocalNativeTopBarHost` / `LocalHostNavigation`）而不是平台判断，页面只读状态。

## 10 改造已有界面（不是重写）

按这个顺序做，每一步都能单独验收：

1. **换形状**：全局 `RoundedCornerShape` → 连续曲率；卡片 20、条目 10、图标 8。这一步立刻"像小米"。
2. **换色阶**：把灰阶换成 100% / 80% / 60% / 40% / `#B2B2B2` 五档，深色用对应白。删掉所有自定义灰。
3. **换构件**：底栏改"胶囊 + 圆钮"，顶栏动作改 42dp 圆钮，分段改胶囊滑块，主按钮改 40dp 胶囊。
4. **换间距**：页面 16/20、分组 12、行 16、底部 60 + 浮起量；小标题 12/8。
5. **上玻璃**：只给顶栏按钮、底栏、必要浮层；先跑 `FROSTED`（无折射），稳定后再开 `SOFT`。
6. **上动效**：卡片入场 → 文字换字 → 材质随滚动 → morph（最后）。
7. **过清单**：`SKILL.md` 的八条交付检查 + `NONE` 档全页可读。

反例：一上来就写 shader、先做 morph，结果形状和灰阶都不对，越做越像"半成品 Material"。

## 11 反模式（一眼假）

- 全屏半透明白 + `backdrop-filter` 一个值到底：没有边缘光、没有方向光、没有厚度。
- 圆角用普通 `RoundedCornerShape`：转角出现"折角"，和真机一比立刻露。
- 底栏贴边通栏 + 48dp 图标按钮：这是 Material，不是 HyperOS。
- 卡片投影 + 描边 + 玻璃三者同时上：层级混乱，真机只有"玻璃边缘光"一种强调。
- 每个可见块都玻璃：玻璃只用于**悬浮构件**与**需要透视的内容**，其余用表面色。
- 动效 500ms 以上、带弹跳的入场：这套语言是"快而准"，不是"活泼"。
